# トラブルシューティング

## 起動・導入

| 症状 | 確認すること |
| --- | --- |
| exe が見つからない | 成功した Actions 実行の Artifact をダウンロードして ZIP を展開するか、開発ガイドに従ってビルドします。ソースの ZIP に exe は含まれません。 |
| ファイル不足と表示される | ソース版は `npm.cmd ci` と `npm.cmd run prepare:assets` を実行します。exe 版はビルド済みのファイルを再取得します。 |
| `py` が見つからない | Python を導入します。Python Launcher がない場合は `python -m venv .venv` を使います。 |
| `npm` が見つからない | Node.js を導入し、新しい PowerShell を開きます。 |
| PowerShell が npm スクリプトを拒否する | ドキュメントの `npm.cmd` / `npx.cmd` を使います。システムの実行ポリシー変更は不要です。 |
| ブラウザーが開かない | ソース版で `app.py --no-browser` を起動し、表示された URL を Edge / Chrome で開きます。 |
| ソースの変更が反映されない | 起動スクリプトは exe を優先します。Python から直接起動し、ブラウザーを再読み込みしてください。 |

## カメラを開始できない

1. Windows カメラ・会議アプリなど、同じ機器を使用するアプリを閉じます。
2. ブラウザーのアドレスバーから、このローカルページにカメラアクセスが許可されているか確認します。
3. **一覧を更新** を押し、内蔵・外付け・仮想カメラのどれを使うか明示的に選びます。
4. スマートフォン連携では、スマートフォン側の接続やカメラ利用許可も確認します。
5. **カメラを開始** を押します。開始中にキャンセルしたい場合は **停止** を押します。

許可前には機器名が見えない場合があります。ブラウザーで許可した後に一覧を更新してください。機器の抜き差しやポート変更でブラウザーの機器 ID が変わった場合も、一覧から選び直します。

Windows カメラアプリで映ることだけでは、ブラウザーのアクセス許可や選択機器が正しいとは限りません。両方で同じ機器を選んでいるか確認してください。

## 映像が黒い・止まる

黒映像の警告は「フレームは届いているが、ほぼ黒い」という意味です。カバー・照明・選択機器・スマートフォン側の映像を確認してください。これだけでカメラの故障とは判断しません。

映像更新が止まった場合は、接続先や他アプリの使用状況を確認し、再接続します。カメラの解像度や FPS は固定しません。複数の対応モードがある機器でも、実際の値はブラウザーとドライバーの調整結果です。

## 映像は出るが認識されない

- **認識モデル** が「準備完了」か確認します。失敗している場合は **認識モデルを再読み込み** を使います。
- **検出を一時停止** していないか確認します。
- 手全体を映し、指先をフレーム外へ出さないようにします。
- 強い逆光や手の重なりを避けます。中指以外の3本を曲げ、短い時間キープします。
- 同じ姿勢を保持したままでは繰り返し反応しません。一度ジェスチャーを戻してください。

判定はデモ向けのヒューリスティックです。医療用途や厳密な姿勢測定を目的としたものではありません。

## 診断情報を共有するとき

「診断情報をコピー」には、表示中のカメラ名やエラー文が含まれます。公開 Issue に貼り付ける前に、機器の個別名称、識別子、ユーザー名、個人フォルダーのパスなどを削除してください。カメラ映像のスクリーンショットや録画は必要ありません。

報告には再現手順、期待した動作、実際の動作、OS・ブラウザーの種類とバージョン、カメラの種類（内蔵・USB・仮想など）を記載してください。安全な共有の詳細は [プライバシー](privacy.md) を参照してください。
